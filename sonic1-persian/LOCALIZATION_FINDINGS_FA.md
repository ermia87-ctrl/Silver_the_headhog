# گزارش شناسایی نوشته‌های Sonic 1 برای فارسی‌سازی

این گزارش از بررسی ROM ارسالی و تطبیق ساختار آن با disassembly عمومی Sonic 1 (شاخه AS) تهیه شده است. در این مرحله هنوز هیچ بایت ROM تغییر داده نشده است.

## نتیجهٔ شناسایی

نوشته‌های بازی یک رشتهٔ متنی ساده و یک‌جا نیستند؛ بخش مهمی از آن‌ها به شکل tileهای تصویری و جدول چیدمان sprite ذخیره شده‌اند. بنابراین جایگزینی متن ASCII به‌تنهایی ترجمهٔ بازی را انجام نمی‌دهد.

| نوشته/بخش | محل نمایش | منبع مرتبط |
|---|---|---|
| PRESS START BUTTON | صفحهٔ عنوان | `_incObj/0E, 0F Title Screen - Sonic, Press Start, TM.asm`, `_maps/Press Start and TM.asm`, گرافیک `artnem/Title Screen Foreground.nem` |
| SONIC TEAM PRESENTS | پیش از صفحهٔ عنوان | `_incObj/8A Credits and Sonic Team Presents.asm`, `_maps/Credits.asm` |
| نوشته‌های تیتراژ و TRY AGAIN | پایان/صفحهٔ ادامه | `_maps/Credits.asm`, گرافیک `artnem/Ending - Credits.nem` |
| Level Select و Debug | منوی انتخاب مرحله/حالت دیباگ | گرافیک `artunc/Level Select & Debug Text.unc` |
| نوشته‌های HUD | داخل مرحله (SCORE/TIME/RINGS و اعداد) | `_maps/HUD.asm`, `artnem/HUD.nem` |

## جزئیات فنی تأییدشده در کد منبع

- شیء صفحهٔ عنوان، نوشتهٔ PRESS START را با انیمیشن sprite جداگانه نمایش می‌دهد؛ نقشهٔ sprite آن در `_maps/Press Start and TM.asm` تعریف شده است.
- نوشتهٔ SONIC TEAM PRESENTS یکی از فریم‌های جدول `Map_Cred` است. متن تیتراژ هم با قطعات sprite و شمارهٔ tileها ساخته می‌شود.
- HUD از قطعات sprite ثابت استفاده می‌کند. بخش SCORE، TIME و RINGS در نقشه‌های HUD تعریف شده و اعداد پویا کنار آن‌ها قرار می‌گیرند.
- در نتیجه، ترجمه فقط نقاشی دوبارهٔ حروف نیست: باید شمارهٔ tileها، مختصات قطعات، طول عبارت و فضای نمایش نیز هماهنگ شوند.

## واژه‌نامهٔ پیشنهادی فارسی

| متن فعلی | معادل پیشنهادی |
|---|---|
| PRESS START BUTTON | برای شروع دکمه‌ای بزنید |
| SONIC TEAM PRESENTS | تیم سونیک تقدیم می‌کند |
| SCORE | امتیاز |
| TIME | زمان |
| RINGS | حلقه‌ها |
| TRY AGAIN | دوباره تلاش کن |
| LEVEL SELECT | انتخاب مرحله |

نام اشخاص در تیتراژ ترجمه نمی‌شود؛ فقط عنوان نقش‌ها و عبارت‌های عمومی فارسی می‌شوند. جهت نوشتار فارسی راست‌به‌چپ است، اما اعداد شمارنده‌ها و نام‌های خاص باید با ترتیب درست باقی بمانند.

## ترتیب درست پیاده‌سازی

1. تأیید revision دقیق ROM با checksum هدر و تطبیق با نسخهٔ disassembly.
2. استخراج و بازکردن گرافیک‌های فشردهٔ Nemesis/Kosinski از محل‌های مشخص‌شده.
3. ساخت فونت فارسی پیکسلی با اندازه و پالت سازگار با بازی.
4. بازطراحی tileها و جدول‌های sprite/map برای هر رشته؛ در صورت نیاز اصلاح کد رسم برای جهت راست‌به‌چپ.
5. ساخت ROM آزمایشی و مقایسهٔ checksum/اندازه، سپس تست صفحهٔ عنوان، HUD، انتخاب مرحله و تیتراژ.

## محدودیت فعلی

ابزارهای بررسی ROM و ساخت اطلس خام در شاخهٔ پروژه ثبت شده‌اند و اجرای خودکارشان موفق بوده است. اطلس خام به‌تنهایی گرافیک‌های فشردهٔ بازی را رمزگشایی نمی‌کند. تا وقتی فونت فارسی، داده‌های فشرده و جدول‌های چیدمان به‌درستی بازسازی نشده‌اند، ساخت یک ROM فارسیِ قابل اجرا قابل ادعا نیست. این مرحله شناسایی و مستندسازی نقاط متنی است؛ هنوز patch فارسی تولید نشده است.
